# 调查与实施记录

调查日期：2026-09-13。

## 结论

选用仓公开源码 + Rime + 白霜小鹤方案，新增的核心只是显示状态与键帽映射。不重写分词、候选排序、用户词频、编辑代理、候选栏、地球键或数字符号键盘。

仓的[公开 README](https://github.com/imfuxiao/Hamster/blob/65693706d01fc6c19ed6071968e542b0a2ef3f36/README.md)明确说明后续商业功能未继续开源。因此不能把[最新皮肤文档](https://ihsiao.com/apps/hamster/docs/guides/keyboard_skins/)中的 JavaScript 动态皮肤能力假设为公开源码已有功能。当前公开版本以 UIKit 标准键盘为主，直接改键帽显示层比移植整个皮肤引擎更小。

## 白霜排序

使用[白霜原生小鹤配置](https://github.com/gaboolic/rime-frost/blob/1f23deea97ee16d529c0a3b2fbc37a2b74f0f491/rime_frost_double_pinyin_flypy.schema.yaml)。该配置含 Lua 过滤器、用户词典以及 `grammar.language: zh-moqi`。只复制字典不足以保留全部排序逻辑。

本工程原样打包方案、词频、过滤器、模型与 OpenCC 文件；唯一新增的 Rime 补丁是默认方案列表只显示小鹤。没有自造候选排序算法，也没有强行冻结用户词频。个人使用历史和引擎版本仍可能影响最终候选次序；尚未做真机候选序列对照，不能声称与任意桌面安装逐项相同。

## 层切换设计

状态输入是 `Rime.getInputKeys()` 和 `getCaretPosition()`，而不是 UI 事件计数。对光标之前、最近显式分隔符之后的小写编码计算奇偶：奇数为韵母层，偶数为声母层。白霜锁定版本未开启首字母简拼，因此完整小鹤音节为两码。若将来自己开启单字母简拼或更改拼写代数，需改为读取 Rime 分段信息，不能继续套用这个判定。

输入含反引号辅码、斜杠符号、大写英文等非音节编码时回退拉丁键帽；不会改写输入字符串。按键气泡从同一状态取文字，防止键帽显示注音而气泡显示字母。既有选词、英文切换、候选栏操作均复用仓。

拼音与注音并不是每个韵母都单符号对应：iang=ㄧㄤ、uang=ㄨㄤ、iong=ㄩㄥ、iu=ㄧㄡ、ui=ㄨㄟ；y/w 是拼音拼写辅助字母，显示 ㄧ/ㄨ。零声母 a/e/o 保持小鹤编码，不新增声调、第三击或其他输入动作。

## 构建决策

上游 ci.yml 使用 macos-13、Xcode 15.0.1、旧 artifact action，且 framework 下载 URL 已失效。新 workflow 使用 macos-15 与当前 runner 的 Xcode，关闭签名进行 archive，然后把主 App 与其扩展直接打包为 IPA。

复用[thomfang/LibrimeKit-iOS](https://github.com/thomfang/LibrimeKit-iOS/tree/5611777f19afa9a431eea8909dde9e88e1d72d0d)的 Boost、Rime、Lua 交叉编译脚本。其 v0.2.2 发布包经下载检查缺少 octagram，所以本工程构建时加入[原版 octagram](https://github.com/lotem/librime-octagram/tree/57d18b9f58e5284bd891d559f6bdd16cf60341e9)，并显式链接、加载 Lua 和 octagram。SwiftPM 的依赖名同步到该构建项目使用的 Boost thread 集合。

缓存框架而非每次重编依赖；源版本、插件版本与准备脚本变化会失效缓存。主要来源用提交哈希固定，框架工程的递归 submodule 按 gitlink 固定；macOS runner、Xcode 和上游依赖下载服务本身并非完全可重复环境。

真机验收顺序：
1. 初始化并离线部署，确认默认选中白霜小鹤。
2. `nihc`、`vsgo`、`xl`、`hl`、`aa`、`ee`、`ah`，观察每击前后的键帽。
3. 组字中逐字删除、清空、移动光标、选中部分候选、整句上屏后继续输入。
4. 中英切换、数字与标点切换、长按/划动、按下后取消、深色模式和横屏。
5. 飞行模式下重启主 App、重新部署并输入；检查个人词频在重启键盘后仍保留。
6. 检查键盘内存和延迟，尤其首次打开较大词库时。未实测前不承诺内存占用或响应时间。

## iOS 范围

[Apple 官方键盘文档](https://developer.apple.com/documentation/uikit/configuring-a-custom-keyboard-interface)规定安全输入框、部分电话输入框会使用系统键盘，App 也可拒绝第三方键盘。不能通过修改仓消除这些约束。「允许完全访问」同时涉及共享容器能力；本方案沿用本地共享词库架构，不接入云输入服务。
